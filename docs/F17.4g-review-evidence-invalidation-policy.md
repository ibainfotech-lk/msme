## Safety objective

Any prior review becomes unusable if it no longer matches the specific business, assessment year, draft ID/revision, claims digest, evidence-set digest, or legal-source digest. Re-review is required if reviewer/professional status changes, consent expires, a retention policy becomes inapplicable, or an append-only invalidation event is present.

The F.17.4g pure function accepts hypothetical **server-trusted** snapshots. It never fetches or validates real evidence, permissions, credentials, professional qualifications, grants, consent records, subscription holds or the database event log. In future real code, authoritative records must be obtained and rechecked in one locked transaction. Do **not** permit frontend callers to submit these snapshots as proof.

## Review bindings

The proposed fingerprint binds `businessId`, `assessmentYearStart`, `draftId`, `draftRevision`, `claimsSha256`, `evidenceSetSha256`, and `legalSourcesSha256` to a particular historical decision ID and date. A mismatch is stale; a digest alone never proves the source document or an approved legal rule.

The current snapshot separately includes the results of hypothetical independent checks for evidence integrity, legal-source review, current reviewer grant, professional credential status, conflict of interest, consent scope/expiry, and approved retention. Missing or false checks fail closed.

The model anticipates append-only invalidation events for: `DRAFT_UPDATED`, `EVIDENCE_CHANGED`, `LEGAL_SOURCE_SUPERSEDED`, `REVIEWER_GRANT_REVOKED`, `APPROVER_GRANT_REVOKED`, `PROFESSIONAL_CREDENTIAL_REVOKED`, `TAXPAYER_IDENTITY_CHANGED`, `CASHBOOK_CORRECTED`, `CONSENT_WITHDRAWN`, and `DECISION_REVOKED`. Any valid event bound to the decision requires a new review. Incorrect tenant, assessment year, decision ID, malformed event or incomplete history fails closed.

The policy cannot establish event-log completeness; the future repository must guarantee append-only storage, read-side integrity checks, concurrency locking, and a complete scoped event stream. The `invalidationHistoryComplete` flag is a *hypothetical trusted future server fact*, not itself proof, and must never be taken from a request.

## No implicit tax approval

Both success-condition and blocked results always return:

- `grantsAuthorization: false`
- `professionalVerificationGranted: false`
- `taxCalculationEnabled: false`
- `taxableIncomeLkr: null`
- `taxPayableLkr: null`
- `paymentDueLkr: null`

An `INDEPENDENTLY_REVIEWED` hypothetical status in this policy does not mean a professional review has been performed in Noteto. It only models a future input state; no real grant/approval exists.
