# F.16.5.4f — Development-only held-account history API

**Status:** Not production-enabled, not attached to the public customer UI. Must pass CI on disposable MySQL 8.4.

## Routes (only when explicitly mounted)

The application mounts `/api/hold-history` only when:

```text
NODE_ENV=development
NOTETO_HOLD_HISTORY_API_ENABLED=true
```

All endpoints require a real authenticated session. Only the editing endpoint writes, and it additionally checks the browser Origin via `requireCheckoutOrigin`.

| Method | Endpoint | Behavior |
|---|---|---|
| GET | `/api/hold-history/businesses/:businessId/entries` | Lists at most 100 existing transactions. In HOLD mode only rows created before `held_at` are visible. |
| GET | `/api/hold-history/businesses/:businessId/reports` | Lists at most 100 report metadata rows. In HOLD mode only snapshots generated on/before `held_at` appear. |
| GET | `/api/hold-history/businesses/:businessId/reports/:reportId/pdf` | Returns stored PDF bytes only after checking tenant, membership, role, provenance and SHA-256. No dynamic report generation. |
| PATCH | `/api/hold-history/businesses/:businessId/entries/:entryId` | Corrects an already existing pre-hold income/expense entry under `transactions.update`, a checked revision, full reason and same-transaction audit. Only in HOLD mode. |

The PATCH body is:

```json
{
  "expectedVersion": 1,
  "amountLkr": "450.00",
  "category": "Sales corrected",
  "description": "Correct historic sale",
  "occurredOn": "2026-10-19",
  "reason": "Original recorded amount was incorrect"
}
```

This route is **not** a create/upsert endpoint. There is no POST/DELETE/new invoice/new report endpoint. `/api/transactions` remains `503 FEATURE_NOT_READY`.

## Additional gates for modifying or retrieving history

- PATCH also requires `NOTETO_HISTORICAL_EDIT_ENABLED=true`.
- PDF retrieval also requires `NOTETO_ARCHIVED_REPORT_DOWNLOAD_ENABLED=true`.
- The list service checks active membership and `transactions.read` or `reports.read` permission, and rejects missing trusted `held_at` for `PAST_DUE` subscriptions.
- Only the backend decides if a business is on HOLD. An unpaid invoice by itself is not sufficient to place a hold.
- Report previews/downloads are of archived PDF bytes only. Correcting an old entry does **not** rewrite any archived report.
- The first 100 results are returned; safe pagination and accessibility remain separate milestones.

## Prerequisites before user rollout

- Real customer user interface (clear hold banner, old-entry editor, report list/download, error messages and accessibility).
- Trusted audited hold transition/grace period, verified payment reconciliation and activation/reinstatement.
- A safe production accounting create/read service for paying customers, with audit/authorization and limits.
- Structured CSRF protection beyond the current same-origin check, abuse controls, input monitoring, production threat review, and no-store caching.
- Production-grade audit retention and archive integrity (least-privilege DB credentials, backups/object storage, lawful deletion).
- End-to-end integration tests using real session cookies and HTTPS origin behavior. The current branch adds service-level integration tests; the HTTP adapter is TypeScript-compiled but not yet end-to-end tested.

**CI success does not authorize deployment or activation.**
