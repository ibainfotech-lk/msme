## Implementation

## Conditions checked

- Development-only feature gate, authenticated actor, business and assessment year.
- Active business and current same-tenant active membership.
- Active/trial subscription in its valid period with no hold.
- Professional credential verified independently, current and non-revoked.
- Explicit grant scoped to actor, action, business and assessment year; valid, independently provisioned, non-revoked and not issued by a conflicted person.
- Case bound to declared taxpayer, named beneficial owners, assessment year, draft revision, evidence SHA-256 and legal-source SHA-256.
- Separate RECOMMEND and INDEPENDENT_APPROVE actions; independent approver not declarant, owner or original reviewer. Approver must see the exact approved recommendation status, revision, scope and digests.
- Incomplete evidence, stale drafts, invalid source metadata, expired grants and conflicted actors fail closed.

## Non-authorization boundary

A positive pure-policy result is **POLICY_CONDITIONS_MET**, **not a live authorization**. Every result, positive or negative, always has:

- grantsAuthorization: false
- taxpayerVerified: false
- taxCalculationEnabled: false
- taxableIncomeLkr: null
- taxPayableLkr: null
- paymentDueLkr: null

The module is NOT invoked by any API or service. The proposed credential and grant snapshots are illustrative future server-trusted facts. Those records are not persisted by F.17.4f. No client value, request-supplied role, UI flag, or digest can replace genuine independently checked evidence. Existing OWNER, taxes.read and taxes.manage permissions grant nothing new.

## Verification gate

Pure policy tests cover no/mismatched credentials, absent or revoked grants, session mismatch, other tenant access, invalid assessment year, HOLD, suspended or expired subscriptions, self-review, self-issued grants, stale evidence, missing or stale recommendations, and self-approval.

The GitHub Actions workflow still includes backend and security, disposable MySQL 8.4, and React TypeScript build. The new policy suite is wired to the backend security job. The policy has no persistence and does not require a new MySQL fixture. **Do not mark F.17.4f green until a fresh branch workflow passes.**
