# Noteto F.16.5.4h — Verified monthly arrears display during account hold

**Development-only integration.** The branch is based on the CI-passing F.16.5.4g commit. This phase has no migration, does not initiate payments and is not production-enabled.

## Customer-facing behavior

The React held-account screen now calls a single authenticated GET endpoint to retrieve a server-generated monthly statement:

```text
GET /api/hold-history/businesses/:businessId/arrears
```

The endpoint is mounted only when `NODE_ENV=development` and `NOTETO_HOLD_HISTORY_API_ENABLED=true`. The underlying service additionally requires:

```text
NOTETO_ARREARS_PREVIEW_ENABLED=true
NOTETO_ARREARS_HISTORY_READY=true
NOTETO_HOLD_BILLING_STATEMENT_ENABLED=true
NOTETO_VERIFIED_PAYMENT_HISTORY_READY=true
```

These switches are *not* a production release plan.

The server checks:
- An authenticated current user with active business membership and `billing.manage` permission.
- Active business and its **current** subscription is `PAST_DUE` with reviewed `held_at`, no client-selected subscription ID.
- Every month from subscription start to the Sri Lankan calendar month containing the statement date has a reviewed ledger row. Missing months fail closed.
- Waived/non-billable months are not charged, and money values are derived using integer cents.
- Allocated payments must have `SUCCEEDED` status, `verified_at`, initiated gateway evidence, a non-empty gateway transaction ID and checkout `PAID`. Missing settlement proof fails closed.
- Every statement response has `paymentActionAllowed: false` and `penaltyLkr: '0.00'`; no late fee policy is activated by this stage.

The screen shows each actually due outstanding month and its verified allocations, total outstanding in LKR, penalty and checked date. It does **not** infer an LKR amount from time elapsed, show a checkout button or activate held subscriptions.

If the arrears ledger/permission/settlement is incomplete, it displays **Balance unavailable — billing review required**, not an assumed zero or partial amount. Existing history viewing and previous report downloads remain separately accessible when authorized.

Example **only if January and February are explicitly billable, due, and unpaid**:

| Month | Outstanding |
|---|---:|
| January 2027 | LKR 499.00 |
| February 2027 | LKR 499.00 |
| Late penalty | LKR 0.00 |
| **Total** | **LKR 998.00** |

## Testing and release boundary

The existing guarded `subscription-arrears.mysql.integration.test.ts` now covers held-mode totals, introductory free-month waivers, missing `held_at`, active-vs-held, absent ledger months, cross-tenant denial, verified payment history readiness, and rejection of allocations without gateway settlement evidence.

The GitHub Actions disposable MySQL 8.4 job and React TypeScript build need to pass on this new branch. Even after CI passes, there is no reviewed production billing due-generation job, no automatic hold/reinstatement, no live bank gateway, no profile editing endpoint and no complete real-customer report pipeline. Do not deploy or run development MySQL fixtures locally.
