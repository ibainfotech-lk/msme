# Noteto F.17.3b — Immutable cashbook PDF snapshots (private pilot)

**Branch**: `feature/f17-3b-immutable-pdf-snapshots`
**Base**: F.17.3 daily/weekly/yearly previews passed GitHub Actions workflow #39, commit `e7d7fa0c452e588bfb488a54093c381a682f00a7`.
**Status**: Development-only; test via disposable CI before any production changes.

## What is implemented

- An existing cash-basis `DAILY`, Monday-based `WEEKLY`, or `YEARLY` report is recalculated using the verified F.17.3 report aggregator under the business/subscription row lock.
- After the same authorization and *within the same transaction*, server creates a bounded one-page standard PDF cash summary and inserts it in **the existing** `archived_report_snapshots` table; the entire transaction rolls back if anything fails. No migrations are added.
- The source of truth is confirmed `cash_transactions` only. **Unpaid sales invoices are never cash income**; no receipt, tax, bank balance or subscription payment is created.
- SHA-256 of the exact PDF bytes, length, generation timestamp, business, subscription, generating user and report period are stored. The existing archive downloader validates checksum and provenance before returning the bytes.
- POST request includes a client-generated, stable UUID `snapshotId`. A retry with the identical UUID, actor, business and period returns the original PDF metadata. Reusing the UUID across tenants/users/periods returns a 409 conflict.
- Database existing primary keys prevent duplicate archive IDs. No overwrite or deletion route exists. **API-level immutability is not a database WORM guarantee**: administrators with unrestricted database permissions could still modify rows, so least-privilege roles, offsite backups and retention controls are required before production.
- Held accounts cannot generate fresh PDFs. The existing `/api/hold-history/.../reports/:reportId/pdf` download flow continues to permit only pre-hold report snapshots when verified archived-report access checks pass.

## Honest PDF scope and localization

The current renderer intentionally emits **English text and numeric LKR summaries only**, using a standard single-page PDF font. Item and category names (which may require Tamil/Sinhala shaping) are not embedded or translated, rather than silently corrupting them. The existing CSV report continues to contain category names in the source language.

This is a technical pilot renderer, **not a complete production-grade, translated financial statement**. A licensed Unicode PDF renderer with tested Tamil and Sinhala shaping, paging, accessibility, fonts and branding is required before multilingual release. The saved document also explicitly states net cash movement is not bank-reconciled cash on hand, profit, VAT or certified tax liability.

## Development-only APIs

Both endpoints require server-side authentication and tenant/business-scoped report permissions.

| Method | Path | Behavior |
|---|---|---|
| `POST` | `/api/reports/businesses/:businessId/snapshots` | Same-origin write, `reports.generate` + `reports.read`, current FULL subscription; idempotent single-transaction archive |
| `GET` | `/api/reports/businesses/:businessId/snapshots/:snapshotId/pdf` | Existing checked archive reader; content type PDF, no-store response; existing hold-aware read capability |
| Other routes | — | Disabled |

Example request:

```json
{"snapshotId":"6e22e35f-8eab-4342-a5ce-ad14fb4b3db5","period":"DAILY","periodKey":"2026-11-20"}
```

Do not confuse this UUID with the PDF checksum; the checksum is computed by the server from the binary PDF. Client-supplied amounts, subscription IDs, PDF bytes and archive timestamps are never accepted.

## Private development feature gates

- `NODE_ENV=development` is required on every involved route and service.
- `NOTETO_F17_REPORT_PREVIEW_ENABLED=true` enables the F17.3 report backend.
- `NOTETO_F17_PDF_ARCHIVE_WRITE_ENABLED=true` enables the PDF snapshot writer.
- `NOTETO_ARCHIVED_REPORT_DOWNLOAD_ENABLED=true` enables existing checksum-validated PDF download.
- `VITE_NOTETO_F17_BOOKKEEPING_UI_ENABLED=true` and `VITE_NOTETO_F17_REPORT_PREVIEW_UI_ENABLED=true` enable the React preview and private PDF button.
- Held-account history remains protected by its existing `NOTETO_HOLD_HISTORY_API_ENABLED` flag and the backend resource-proof checks.

Never set any of these flags in production as a workaround. No production migrations or customer DB operations are part of this milestone.

## CI coverage

The `test:mysql-cashbook-reports` suite now also tests:
- PDF bytes, PDF header, checksum and nonzero size after a committed archive
- No extra cash transactions on save
- Same-ID retries preserving prior archived bytes even after a later audit correction
- Held-account pre-hold PDF download and rejection of new PDF generation
- Tenant isolation, wrong-period UUID conflicts, generator/read-permission checks
- Production-disable and write-flag fail-closed checks before opening a DB

This extends the F17.3 suite from 14 to **20** integration tests, with no migration change (still **21**). The existing GitHub Actions workflow runs this suite against disposable MySQL 8.4, plus security regression and React TypeScript build.
