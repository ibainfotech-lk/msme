# F.16.5.4d — Previously saved report access while on hold

**Development only.** The migration and internal download service are reviewed in disposable MySQL 8.4 CI first. Do not deploy to customer/production databases.

## Goal

When a subscription is placed on payment hold, keep the customer able to view and download PDF reports that were already generated **before the hold timestamp**, while preventing fresh report generation.

The report retrieval service:
- demands an active business membership and `reports.read` permission;
- reads the current subscription status and the trusted `held_at` timestamp;
- loads an existing report archive by business ID and report ID;
- grants access under `PAST_DUE` only for reports generated on/before the hold;
- returns exact stored bytes after checking PDF header, byte length and SHA-256;
- NEVER calls a report generator, alters financial records, starts a payment or changes subscriptions;
- is disabled in production, has no HTTP route and is not integrated with the frontend.

The schema stores `pdf_bytes` with `content_sha256` and strict tenant foreign keys, plus triggers that block regular SQL UPDATE and DELETE for ordinary archives.

## Important missing components

- The actual daily/weekly/yearly report generator and archive creation workflow are **not implemented**. This branch does not generate reports.
- Transaction APIs currently return `503 FEATURE_NOT_READY`; old-entry editing requires a separate cash-transactions schema, immutable entry edit audit, provenance check and tenant-scoped API.
- The reviewed `PAST_DUE` transition must set `held_at` as part of one audited transaction. There is no automatic hold transition yet. A missing timestamp makes historical report access fail closed.
- The application needs a secure download route with CSRF/session/role checks, no cache and safe Content-Disposition, and an actual UI. This branch does not attach one.
- Permanent immutability triggers must be reconciled with lawful retention/deletion and privacy obligations before any real customer data is stored. These triggers are NOT ready for live data.
- Before production, confirm PDF rendering, secure file encryption/backups, retention, auditing and access to previous subscriptions' historical reports.

**CI green means tests pass on an ephemeral database. It does not enable the feature for users.**
