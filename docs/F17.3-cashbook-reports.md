# Noteto F.17.3 — Cash-basis day, week and year report previews

**Branch**: `feature/f17-3-cashbook-report-previews`
**Based on**: F.17.2 passed CI workflow #38, commit `3fc01f98832b1cf401f15b8bb562d041d63d4d5e`.
**Deployment**: Development-only feature. Production is disabled. No new migrations, PDF snapshots or customer ledger changes.

## Accounting interpretation

This stage generates *on-demand previews* from actual `cash_transactions` belonging to exactly one authorized business.

- `INCOME` is cash already received, not a sales invoice that has yet to be settled.
- `EXPENSE` is cash already paid, not a pending supplier bill.
- Net cash movement = cash in − cash out, calculated in exact integer cents from MySQL decimal aggregates; can be negative.
- `cash_transactions` contain manual cash-basis records, not bank-reconciled account balances. Since verified opening cash on hand is not yet available, **do not label net movement a closing cash/bank balance**.
- Cashbook totals are **not taxable income**, VAT, accrual profit, or tax estimates.
- Reports display the *current audited transaction state*; if a previous entry was corrected, it appears at its corrected date/value and isn't double counted. Historical PDF snapshots remain immutable separately.

## Report periods

- **DAILY**: YYYY-MM-DD; cash movements on the specified local calendar date.
- **WEEKLY**: YYYY-MM-DD ISO Monday; seven local days Monday through Sunday, including zero-activity days.
- **YEARLY**: YYYY; 12 month totals January–December including zero-activity months.

All periods use the **Asia/Colombo** reporting calendar, and future start dates are forbidden. The 4-digit year must be between 2000 and the current Colombo year. SQL filters on the cash transaction's stored DATE field and never uses a browser-specific timezone to group cash entries.

Income/expense totals are grouped by date and category, keeping exact decimals. The GROUP BY query is capped at 10,001 rows and intentionally fails closed if there are over 10,000 groups; it **never returns understated totals from partial data**. Each report is generated in a single MySQL transaction with business/subscription locks to serialize against concurrent bookkeeping changes and return one coherent view.

## Authorization and production guard

- Authenticated server-side session, business ACTIVE, active membership, role permission `reports.generate`, current ACTIVE/TRIALING subscription, legitimate subscription effective start and unexpired billing/trial interval.
- `GENERATE_REPORT` capability is checked under the existing hold policy. Held, expired, suspended, pending and unauthenticated users cannot generate a fresh report. On hold, users may still retrieve **previous immutable archived reports** through the existing separate archive download service.
- Backend endpoint exists only when `NODE_ENV=development` and `NOTETO_F17_REPORT_PREVIEW_ENABLED=true`; otherwise returns 503. The report UI additionally requires Vite development mode, `VITE_NOTETO_F17_BOOKKEEPING_UI_ENABLED=true` and `VITE_NOTETO_F17_REPORT_PREVIEW_UI_ENABLED=true`.
- Both router and internal service are gated; no new financial table is written, no migration added, no invoice created, and no PDF archive generated.

## API

`GET /api/reports/businesses/:businessId/preview?period=DAILY&periodKey=2026-11-20`

Responses provide totals (`cashInLkr`, `cashOutLkr`, `netMovementLkr`, entry counts), day/week or monthly breakdowns and a category breakdown. Explicit flags `cashbookOnly:true`, `invoiceAmountsIncluded:false`, `reportSnapshotSaved:false`, `pdfGenerated:false`, `reconciledOpeningBalanceAvailable:false` distinguish a live preview from an approved bank statement or legally compliant financial statement.

All non-GET routes return 405 when the dev feature is enabled. The query schema rejects extra parameters (e.g. a request to add invoices).

## CSV and archived PDFs

The private multilingual (Tamil, Sinhala, English) React screen shows the period summary and offers a **CSV download of the live report** with CSV formula injection protection. A CSV download is not a stored or signed PDF; existing `archived_report_snapshots` PDFs are preserved without modification. For future production report downloads, design a reviewed, immutable PDF snapshot writer with content hash, deterministic period/date identity, authenticated role and hold-aware retrieval. Do not retroactively replace archived PDFs when a user edits historic entries.

## Disposable MySQL CI

The new `test:mysql-cashbook-reports` suite tests:
- Exact LKR cents, cash-in/out/net, entry counts, category totals
- Monday–Sunday week boundaries and 12-month year grouping
- Unpaid invoices completely excluded from the cashbook
- Audited corrections reflected once in live reports
- Tenant permissions, trial access and held/expired/suspended rejection
- No report archive or cashbook writes
- Invalid dates/queries, session auth, HTTP 405 and production disabled

The migration count remains **21**, unchanged from F.17.2. All existing database tests still run.
