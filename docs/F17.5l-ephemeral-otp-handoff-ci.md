## Reason for this milestone

F.17.5k established that an OTP challenge, its hashed secret, an idempotent dispatch reservation and its initial journal event are committed atomically. However, the test deliberately **discarded** the generated plaintext code, so it was not possible to prove a real code would match the stored hash at a private sender. This increment introduces a narrow in-memory bridge **exclusively to an injected fake send function in disposable CI**, without adding an SMS-capable runtime dependency.

## Changes

- `server/src/services/otp-dispatch-journal.service.ts` now privately factors the F.17.5k atomic reservation method into an internal function returning a short-lived code and snapshot. The original public `createReservedOtpChallengeInDisposableCi()` still returns **only** the safe snapshot, preserving compatibility.
- Adds `exerciseEphemeralOtpHandoffInDisposableCi()`, which, for a fresh reservation only:
  1. Enforces the full GitHub Actions disposable environment gate.
  2. Atomically creates the code's bcrypt hash, challenge, dispatch record and first event.
  3. Commits the **single irreversible dispatch claim before invoking the fake send port**.
  4. Passes the plaintext code only to the injected in-memory test callback. No URL, fetch, SMS SDK or credential is imported.
  5. Records an accepted synthetic provider UID as `ACKNOWLEDGED` (never delivered or OTP-verified).
  6. Leaves exceptions, invalid responses and persistence failures as `DISPATCH_UNKNOWN`, for later reconciliation. It never retries an attempt.
- `server/tests/otp-ephemeral-handoff.mysql.integration.test.ts` adds **8** disposable MySQL integration groups, including bcrypt-match, response redaction, replay refusal, simulated timeouts, malformed UID, one-time challenge consumption, competing idempotency keys and disabled-production gate.
- `.github/workflows/noteto-reconciliation-security.yml` runs the new test suite after all previously passing F.17.5i–k suites.

## Security guarantees

- Existing `auth.routes.ts`, `otp.service.ts`, user registration/checkout, e-SMS sandbox transport and application startup have **not** been modified or wired to this test path.
- The random six-digit code is not returned by the public function, stored in the journal, logged, passed to a browser, saved in plaintext, or sent over a network. It is visible only inside the CI fake callback, which test code must not log. The code can be consumed once using existing hashed-code verification.
- Even a provider-accepted status means **accepted for processing**, not delivered, OTP-verified, logged in or subscription activated.
- The safe result always includes `resendPermitted:false`, `otpVerified:false`, `sessionAuthorized:false`, `businessActivated:false`. Replay returns `REPLAY_NO_SEND`.
- The fail-closed gate uses a disposable CI database identity, marker, synthetic test HMAC key and dummy credentials. It is not a trustworthy production permission model and must **never be copied into live configuration**.

## Remaining release blockers

The fake-code handoff is a test of secure secret ownership, **not production authentication**. Before real staging delivery, require independently approved NOTETO sender ID, an authorized provider sandbox arrangement with test numbers, secure token storage, per-phone/IP/device abuse controls, idempotent durable dispatch/reconciliation, privacy and language review, and an authenticated staging-only network execution path. Current OTP code creation is separate from the live route and requires a deliberate integration design.

Separately, Noteto still needs verified Commercial Bank checkout, subscription activation/renewals, production database and secret management, complete cross-feature acceptance tests and release approval. Tax calculation and professional verification remain disabled.
